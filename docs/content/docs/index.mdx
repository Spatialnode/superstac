**Many catalogs. One search.**

Your data lives across catalogs. SuperSTAC gives you one place to search them: register compatible STAC APIs, submit a query, and work with a combined set of items.

The same Rust engine powers a Python package, a Rust library, and a command-line tool. It handles source selection, concurrent requests, collection and asset aliases, duplicate IDs, and per-catalog failures.

For the background and motivation, read [Introducing SuperSTAC: Many catalogs. One search.](https://www.spatialnode.net/articles/introducing-superstac-many-catalogs-one-search2a5e11)

## What you can build

Search imagery across public and private-compatible endpoints, create a shared collection vocabulary for your application, or explore catalog availability from the terminal. SuperSTAC returns STAC item metadata; asset downloads and processing stay in your existing workflow.

## Before you start

SuperSTAC is **alpha software**. Start with [installation](/docs/start/installation), then the [quickstart](/docs/start/quickstart). Read the [current limitations](/docs/reference/status) before relying on the API in production.
