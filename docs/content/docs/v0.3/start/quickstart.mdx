## Run the search

<Tabs items={["Python", "JavaScript", "Rust", "CLI"]}>
<Tab value="Python">

Save this as `search.py`. Run `python search.py`, `uv run search.py`, or `poetry run python search.py`, depending on your environment.

```python title="search.py"
import json
from pathlib import Path
from superstac import Client

catalogs = [
    {
        "id": "earth-search",
        "url": "https://earth-search.aws.element84.com/v1",
    },
    {
        "id": "microsoft",
        "url": "https://planetarycomputer.microsoft.com/api/stac/v1",
    },
]
client = Client(catalogs=catalogs)
try:
    result = client.search(
        collections=["sentinel-2-l2a"],
        bbox=[6, 45, 7, 46],
        datetime="2024-06-01T00:00:00Z/2024-06-30T23:59:59Z",
        limit=5,
    )
    for item in result.items():
        print(item["id"], item["properties"].get("datetime"))
    for failure in result.metadata["failures"]:
        print("Catalog failed:", failure["catalog_id"], failure["reason"])
    Path("items.geojson").write_text(
        json.dumps(result.to_geojson(), indent=2), encoding="utf-8"
    )
    print(f"Saved {len(result)} scene records to items.geojson")
finally:
    client.shutdown()
```

<Tab value="JavaScript">

Use this in the browser entry point of your app after [installing the WASM package](/docs/v0.3/wasm/overview#install). It writes scene IDs, source catalogs, and GeoJSON to the browser console. For a complete page with a button and visible results, use the [browser app example](/docs/v0.3/wasm/overview#put-it-on-a-page).

```js title="search.js"
import init, { SuperSTAC } from '@spatialnode/superstac-wasm';

await init();
const client = new SuperSTAC({
  catalogs: [
    {
      id: 'earth-search',
      url: 'https://earth-search.aws.element84.com/v1',
    },
    {
      id: 'microsoft',
      url: 'https://planetarycomputer.microsoft.com/api/stac/v1',
    },
  ],
});

try {
  const result = await client.search({
    collections: ['sentinel-2-l2a'],
    bbox: [6, 45, 7, 46],
    datetime: '2024-06-01T00:00:00Z/2024-06-30T23:59:59Z',
    limit: 5,
  });
  for (const { item, seen_in } of result.items) {
    console.log(item.id, seen_in);
  }
  for (const failure of result.metadata.failures) {
    console.warn(failure.catalog_id, failure.reason);
  }
  const geojson = {
    type: 'FeatureCollection',
    features: result.items.map(({ item }) => item),
  };
  console.log(geojson);
} finally {
  client.free();
}
```

<Tab value="Rust">

Create an application and add the [Rust dependencies](/docs/v0.3/rust/overview#dependencies). Save the [sample configuration](/superstac/versions/v0.3/examples/superstac.yml) as `superstac.yml` in the project root, then put this in `src/main.rs` and run `cargo run`.

```rust title="src/main.rs"
use superstac_config::init_from_yaml;
use superstac_core::models::storage::Storage;
use superstac_engine::SuperSTACEngine;
use superstac_search::query::SearchQuery;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let storage = init_from_yaml(Storage::Memory, "superstac.yml")?;
    let engine = SuperSTACEngine::new(storage);
    let query = SearchQuery {
        collections: vec!["sentinel-2-l2a".into()],
        bbox: Some(vec![6.0, 45.0, 7.0, 46.0].try_into()?),
        datetime: Some(
            "2024-06-01T00:00:00Z/2024-06-30T23:59:59Z".into(),
        ),
        limit: Some(5),
        ids: None,
        intersects: None,
        sortby: None,
    };
    let result = engine.search(query).await;
    engine.shutdown().await;
    let result = result?;
    for entry in result.items {
        println!("{} from {:?}", entry.item.id, entry.seen_in);
    }
    for failure in result.metadata.failures {
        eprintln!("{}: {}", failure.catalog_id, failure.reason);
    }
    Ok(())
}
```

<Tab value="CLI">

Save the [sample configuration](/superstac/versions/v0.3/examples/superstac.yml) as `superstac.yml` in the directory where you run the command.

```bash
superstac --json search \
  --collection sentinel-2-l2a \
  --bbox=6,45,7,46 \
  --datetime 2024-06-01T00:00:00Z/2024-06-30T23:59:59Z \
  --limit 5 > results.json
```

Open `results.json` to see the items and search metadata. With [jq](https://jqlang.org/) installed:

```bash
jq '.metadata' results.json
jq '{type: "FeatureCollection", features: [.items[].item]}' \
  results.json > items.geojson
```

## What to expect

- **Up to five items per catalog.** Two catalogs can return up to ten items before duplicate IDs are removed.
- **Source coverage can differ.** Different providers do not always return the same scenes or use the same IDs.
- **Failures are part of the response.** Check `metadata.failures` even when the call succeeds. Zero items can mean either no matches or unavailable catalogs.
- **These are scene records.** GeoJSON contains footprints, properties, and asset links—not image pixels.

The native clients check health and discover collections before their first search. Browser searches go directly to the configured catalogs, which must allow browser requests.

## Make it yours

| To… | Change… |
| --- | --- |
| Search another place | `bbox`, in west, south, east, north order |
| Choose different dates | `datetime`, as `start/end` |
| Use another dataset | `collections`; [discover IDs first](/docs/v0.3/guides/catalogs) |
| Get more records | `limit`, up to the configured per-catalog cap |
| Use consistent names | [Collection and asset aliases](/docs/v0.3/guides/aliases) |
| Reuse metadata locally | [GeoParquet inventories](/docs/v0.3/guides/geoparquet) |

For more complete workflows, see [search recipes](/docs/v0.3/guides/recipes).
